# ☸️ K3s Local Cluster (Action)

This module manages a local ephemeral Kubernetes (K3s) cluster with optional data persistence. It allows you to quickly spin up a cluster, connect local tools (like `kubectl` or `k9s`), and destroy the environment when needed.

## 📋 Prerequisites

* **Dagger CLI** installed.
* **kubectl** or **k9s** installed on your host machine (to interact with the cluster).

---

## 🚀 How to Use

This workflow requires **two terminals**: one to keep the server running and another to interact with it.

### 1. Start the Cluster (Terminal A)

In the first terminal, start the service. It is **mandatory** to map port `6443` so your host can access the Kubernetes API.

```bash
dagger call kns service up --ports 6443:6443

```

> **Note:** The terminal will "hang" displaying logs. This is normal. The cluster is alive and running as long as this command is active.

### 2. Connect to the Cluster (Terminal B)

Open a second terminal or tab to download the configuration file (`kubeconfig`) generated by Dagger:

```bash
# 1. Download the configuration file
dagger call kns get-config export --path ./kubeconfig.yaml

# 2. Set the environment variable to use this file
export KUBECONFIG=$(pwd)/kubeconfig.yaml

# 3. Test the connection
kubectl get nodes
# or
k9s

```

### 3. Stop the Cluster (Stop)

To temporarily shut down the cluster, go to **Terminal A** and press:

`Ctrl + C`

**Important:** This only stops the process. Your Pods, Deployments, and configurations **will be preserved** in the Dagger cache. If you run the `up` command again later, the cluster will resume with the same state.

### 4. Reset / Destroy (Reset)

If you want to wipe everything and start with a fresh, empty cluster next time:

```bash
dagger call kns reset

```

*This commands cleans the persistence volume (`varlibdagger`).*

---

## 🛠️ Available Commands

| Function | Dagger Command | Description |
| --- | --- | --- |
| **Start** | `call kns service up --ports 6443:6443` | Starts the K3s server. Requires port mapping. |
| **Config** | `call kns get-config export --path <file>` | Generates the `kubeconfig.yaml` pointing to `localhost`. |
| **Reset** | `call kns reset` | Deletes all data from the persistent volume. |
| **K9s Internal** | `call kns kns-internal` | (Optional) Opens a terminal with K9s running *inside* the Dagger container. |

## ⚙️ Technical Details

* **Port:** The cluster exposes port `6443` (K3s default).
* **Persistence:** Data is stored in a Dagger Cache Volume named `varlibdagger`.
* **Localhost:** The generated `kubeconfig` is automatically configured with `server: https://127.0.0.1:6443` for external access.
